# 보고서함

앱의 **통계 > 보고서함**에 보이는 보고서 목록입니다. 기본 브랜치의 `reports/reports.json`을 앱이 바로 받아갑니다
(`https://raw.githubusercontent.com/<owner>/<repo>/HEAD/reports/reports.json`, 반영까지 몇 분).

보고서를 올리려면 `reports` 배열 맨 앞에 항목을 추가하고 기본 브랜치에 합칩니다. 앱을 새로 만들 필요는 없습니다.

```json
{
  "id": "2026-11-21-주제",            // 겹치지 않는 이름 (올림 표시에 씀)
  "title": "보고서 제목 (카드 표지에 들어감)",
  "date": "2026-11-21",
  "summary": "목록에 보일 한두 줄",
  "thread": "스레드에 올릴 글 (500자 이내)",
  "talk": "오픈톡에 올릴 짧은 글 (비우면 thread를 씀)",
  "blog": { "title": "지역·핵심 낱말이 앞에 오는 제목", "body": "첫 문단 → ■ 소제목 3개 → ■ 한눈에 정리 → 마무리", "tags": ["태그"] },
  "cards": [ { "title": "카드 한 장의 제목", "points": ["항목: 내용", "항목: 내용"] } ],
  "sources": ["자료 이름 — https://주소"]
}
```

- 숫자·날짜는 `sources`에 적은 자료에 있는 것만 씁니다. 확인하지 못한 내용은 쓰지 않거나 확인하지 못했다고 적습니다.
- 말투: 스레드(`thread`)는 반말, 블로그·오픈톡은 존댓말.
- 카드 한 장에는 4줄 안팎, 항목 10자·내용 28자 이내가 보기 좋습니다.

## 보고서에 쓰는 자료

보고서의 실거래·경매·호가 숫자는 이 저장소의 `store` 브랜치에 모인 자료로 씁니다. 자세한 내용은 [`docs/my-data.md`](../docs/my-data.md).

1. 메인 단지는 `store` 브랜치의 `main/my.json`에 분석이 이미 들어 있음 (3시간마다 갱신)
2. 다른 지역은 Actions **my**를 시군구·기간을 넣어 실행 → 국토부 실거래가 `store` 브랜치에 모임
3. `node collector/collect.js summary --regions 강남구 --months 6 --apt 은마`로 단지·면적별 건수·중간값·최고가를 뽑음
4. 뽑은 숫자로 보고서를 쓰고, `sources`에 "국토교통부 실거래가 공개시스템 (YYYY-MM-DD 받음)"을 적음

실거래 원자료는 30일 뒤 지워지는 임시 자료라, 보고서에는 받은 날짜를 꼭 적습니다.

## 내 단지 (메인 단지 분석 · 경매정보)

앱의 **내 단지** 탭은 `store` 브랜치의 `main/my.json`을 받아 보여줍니다.
메인 단지는 `config/main-complexes.json`에서 바꿉니다. 단지 분석과 경매 물건마다 올릴 글이 보고서와 같은 꼴(`post`)로 들어 있습니다.
